2. 核心模块深度分析

2.1. 数据流水线 (Data Pipeline)

YOLO 数据准备 (prepare_yolo_dataset.py)

  • 目的: 将视频序列数据转换为 YOLO 所需的离散图像数据。
  • 关键逻辑:
    • 采样策略: 为了避免数据冗余，脚本不会使用视频的所有帧。通过 --frames-per-seq 参数（默认 5），从每个视频序列中随机抽取 N 帧。这保证了数据集的多样性，防止模型过拟合于某个特定背景。
    • 坐标转换: 原始 JSON 标签通常是 [x, y, w, h] (像素值)，YOLO 需要 [class_id, center_x, center_y, w, h] (归一化值)。脚本自动完成此转换。
    • 目录扁平化: 将不同序列文件夹下的图片统一复制到 images/train 或 images/val，并生成对应的标签文件。

NAS 数据加载 (nas_tracker/data/anti_uav.py)

  • 类: AntiUAVPairDataset
  • 目的: 为孪生网络 (Siamese Network) 提供成对的训练数据。
  • 关键逻辑:
    • 模板与搜索区域 (Template & Search): 对于每个样本，随机选择同一序列中的两帧。一帧作为模板 (Template)（代表目标外观），另一帧作为搜索帧 (Search)（需要在其中找到目标）。
    • 时间间隔控制: max_frame_gap 参数限制了两帧之间的最大时间跨度，确保目标外观变化不会过大。
    • 动态裁剪: 根据 Ground Truth 动态裁剪出以目标为中心的图像块，并缩放到固定尺寸（模板 128x128，搜索区域 256x256）。

2.2. NAS 跟踪器架构 (nas_tracker/models/supernet.py)

本项目使用基于 One-Shot NAS 的孪生网络架构。

  • 超网 (Supernet): 一个包含所有可能子网的大型网络。
    • ChoiceBlock: 网络的基本构建块。每个 Block 不是单一的卷积层，而是包含多个并行的候选操作（如不同 Kernel Size 的卷积、不同扩张率的 MBConv）。
    • 权重共享: 所有子网共享同一套 Supernet 权重。训练 Supernet 等同于同时训练了成千上万个子网。
  • 前向传播 (Forward):
    • 输入: Template 图像 + Search 图像 + arch_choices (架构编码)。
    • 过程: 两个分支分别提取特征 -> 特征融合 (互相关/Concat) -> Head 预测 (分类+回归)。
    • arch_choices: 一个整数列表，指定了每一层具体使用哪个候选操作。

    关于 的说明:
    乘以 是为了进行数值归一化 (Normalization)。

    • 数量级匹配: IoU 是 0~1 的小数，而原始 Cost (FLOPs) 通常是百万级 () 的整数。
    • 单位转换: 将单位从“个”转换为“百万 (Million)”。例如 5,000,000 FLOPs 变为 5.0。
    • 作用: 使得 Cost 与 IoU 处于同一数量级，方便通过 (如 0.05) 进行加权平衡，防止 Cost 完全主导 Fitness 函数。

  • 搜索流程:

    1. 初始化: 随机生成 N 个架构作为初始种群。
    2. 评估: 在验证集上测试每个架构的 IoU，计算 Fitness。
    3. 进化循环:
      • 选择: 保留 Fitness 最高的 Top-K 个架构作为“父母”。
      • 变异 (Mutation): 随机修改父母架构的某些层，生成“子代”。
      • 更新: 将子代加入种群，重新评估并排序。
    4. 输出: 经过多轮进化后，Fitness 最高的架构即为 best_arch。

2.4. 联合推理逻辑 (detect_and_track.py)

  • 类: DetectorTracker
  • 状态机:
    1. 初始化 (Init): 视频第 0 帧，或跟踪丢失时。调用 YOLO 检测器进行全局搜索。
    2. 跟踪 (Track):
      • 使用上一帧的目标位置裁剪 Search Region。
      • 输入 NAS Tracker 预测当前帧的目标位置。
      • 如果预测置信度 (Score) 低于阈值，标记为“潜在丢失”。
    3. 重检测 (Re-detect):
      • 定期重检测: 每隔 detect_interval 帧，强制运行一次 YOLO。
      • 局部优化: 此时 YOLO 不扫描全图，只扫描跟踪器预测位置周围 local_ratio 倍的区域。这既校正了跟踪漂移，又保持了高速度。
      • 融合: 如果 YOLO 检测到了目标，且与跟踪器预测位置 IoU 较高，则更新跟踪器模板；否则信任置信度更高的一方。

2.5. 理论与代码对应 (Theoretical Correspondence)

本项目实现了 One-Shot NAS 的核心思想，代码与学术论文中的公式对应关系如下：

1. 超网训练 (Supernet Training)

  • 代码位置: nas_tracker/trainer/supernet_trainer.py
  • 实现: SupernetTrainer.train() 方法。
  • 细节:
    • 随机采样: 在每个训练 Step 中，self.model(template, search) 会调用 SiameseSuperNet.forward()，该方法默认随机采样一个架构 (sample_random_architecture) 进行前向传播。这相当于在优化共享权重 时，随机遍历搜索空间 中的子网。
    • 损失函数详解: 代码中具体的训练目标函数 由两部分组成：
      • (定位损失): 使用 Smooth L1 Loss 回归包围框坐标。
      • (分类损失): 使用 BCEWithLogitsLoss (二元交叉熵) 区分前景和背景。
      • 权重: 代码中取 ，即主要关注定位准确性，兼顾前景分类。

3. 差异说明

  • ImageNet 预训练: 论文公式 (2) 提到了 Backbone 的 ImageNet 预训练。本项目为了简化流程，直接在 AntiUAV 数据集上从头训练 Supernet (Scratch Training)，省略了显式的预训练步骤。
  • 搜索空间: 论文公式 (3) 提到同时搜索 Backbone () 和 Head ()。本项目目前仅实现了 Backbone 的搜索 (SiameseSuperNet.blocks)，Head 部分采用固定的 MLP 结构。

3. 关键配置参数说明 (nas_tracker/config.py)

参数类 参数名 默认值 含义与调整建议
DataConfig subset_ratio 1.0 数据使用率。1.0 表示使用全量数据。调试时可设为 0.1 以加快速度，正式训练建议 1.0。
seq_len 2 孪生网络输入的帧数对（模板+搜索）。
SupernetConfig base_channels 48 基础通道数。决定模型宽度。值越大模型越强但越慢。
stages 3 网络阶段数（下采样次数）。
TrainConfig epochs 50 训练轮数。NAS 训练通常需要较多轮数才能收敛。
lr 5e-4 初始学习率。
SearchConfig population_size 32 进化算法的种群大小。
evolve_iters 30 进化迭代次数。次数越多搜索越充分。
latency_weight 0.05 速度权重。值越大，搜索出的模型越轻量（但也可能精度越低）。

4. 常见问题与调试

  1. 跟踪器跟不住 (Drift):
    • 原因: 训练不足或模板更新不及时。
    • 解决: 增加 epochs，增大 base_channels，或在推理时减小 detect_interval（增加重检测频率）。
  2. 检测器误报 (False Positive):
    • 原因: 背景复杂或训练数据中负样本不足。
    • 解决: 提高推理时的 --conf 阈值，或在训练 YOLO 时加入更多背景图片。
  3. 速度太慢:
    • 原因: 模型过大或重检测太频繁。
    • 解决: 增大 latency_weight 重新搜索轻量级架构，或增大 detect_interval。
