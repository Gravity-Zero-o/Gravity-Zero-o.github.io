问题背景

在 Firefly RK3588 平台（Ubuntu 22.04）上编译 ROS 2 工作空间 ytjy-ros2/ros2 时，执行 colcon build 出现一系列错误，主要包括：

  • PermissionError: [Errno 13] Permission denied: 'log'
  • Could not find ament_cmake
  • ModuleNotFoundError: No module named 'ament_package'

这些问题表面看起来零散，实际存在清晰的因果链，核心原因是：

sudo 构建污染了工作空间 + ROS 2 Python 依赖不完整

本文记录完整排查与修复过程，便于复现与迁移。

一、问题现象汇总

1. 普通用户执行 colcon

报错：

说明 colcon 无法在当前工作空间创建 log/ 目录。

2. 使用 sudo 构建

可以进入 CMake 阶段，但很快失败：

并伴随 airsim_interfaces / px4_msgs 等包级联失败。

二、根因分析

1. 工作空间权限被 sudo 污染

此前曾执行过：

导致：

  • ros2/ 目录或其子目录（build / log / install）由 root 创建
  • 普通用户 firefly 无写权限
  • 后续 colcon build 无法创建 log/

这是 Linux 文件系统的必然结果。

Step 1：修复工作空间权限（必须）

Step 3：清理并重新构建（不要 sudo）

至此，工作空间应可正常编译。

四、关键经验总结

1. 永远不要用 sudo colcon build

  • colcon build 是 用户态行为
  • sudo 会：
    • 破坏目录权限
    • 隔离 ROS 2 环境变量
    • 制造长期隐蔽问题

一旦使用 sudo，必须通过 chown 或重建目录恢复。

QGC里的飞控参数设置

将飞控固件烧录之后，首先在QGC里面设置飞控的参数

插上USB之后，过几秒钟QGC可以显示连接了飞控，然后parameter里面就有飞控的参数了。

名称 参数 用途
SYS_HITL HITL enabled 开启硬件在环功能
UXRCE_DDS_CFG TELEM 2 飞控的telem2接口和 ttl转usb连接
SER_TEL2_BAUD 921600 8N1 设置串口波特率，然后3588里面也要相同的参数才行
COM_RC_IN_MODE Joystick only 设置使用摇杆控制（没有遥控器）
COM_ARM_WO_GPS Warning only 没有GPS也能arm，否则容易飞不起来
EV_TSK_RC_LOSS Enabled 📌重要：允许没有遥控的时候飞行（开了这个，Airsim里面就不会出现Waiting valid gps了），之前总是没有GPS
MAV_USEHILGPS Enabled 也许默认是开的？没印象改过，反正要开才行

记得在Airfame里面，设置为HIL Quadcopter X 不过这个图标一个固定翼的

YOLO / Track Review Fixes

本文记录根据外部检查建议对 lesson6_yolo.py、lesson6_track.py 以及必要 launch 参数做的最小修改。

已修改

建议问题 原来 现在 对应状态
Track 中 LiDAR pitch 与建议中的 AirSim 配置不一致 lidar_pitch_deg = -10.0，launch 也传 -10.0 lidar_pitch_deg = -20.0，launch 同步传 -20.0 已对应
LiDAR 覆盖深度时可能把背景点当目标 角度匹配后，如果没有和相机深度接近的点，仍会继续从角度候选点里选 相机深度有效时，先用动态距离门限 max(lidar_search_radius, 0.2 * camera_depth, 3.0) 做一致性检查；没有一致点就直接返回 camera_depth 已对应
LiDAR 搜索半径过小 lidar_search_radius = 1.5 lidar_search_radius = 3.0，launch 同步传 3.0 已对应
YOLO 深度采样窗口固定且偏小 固定 depth_window_px=5 的中心小窗口，取 median 根据 bbox 尺寸生成 ROI，半径限制在至少 4 像素、最多 20 像素；有效深度取 20 分位数 已对应
YOLO 缺少最大深度过滤 只检查 range > 0.05 新增 max_valid_depth=120.0，超过该值不发布测量 已对应
RGB/Depth 同步窗口过窄 queue_size=4, slop=0.03 queue_size=2, slop=0.15 已对应
每帧都 result.plot() 导致推理链路变慢 每帧绘制并发布 /yolo/output 新增 publish_annotated 参数，默认 False；需要调试图像时再打开 已对应
YOLO 没有使用 AirSim 发布的真实相机内参 只用 launch 中的 FOV 推算 fx/fy/cx/cy 订阅 /airsim_node/PX4/<camera>/camera_info，可用时直接使用 CameraInfo.k 已对应
YOLO 推理缺少实时参数 使用 Ultralytics 默认推理参数 新增 yolo_imgsz、yolo_max_det、yolo_device、yolo_half；launch 默认 imgsz=512,max_det=1 已对应
Track 速度明显偏慢 max_speed=3.0，速度指令由 v + a*dt 小步积分得到 默认 max_speed=15.0，并新增 velocity_setpoint_mode=desired，直接发布制导计算出的期望速度 已对应
Track 默认参数与 MATLAB 基线不一致 ROS 默认 hfov=90,vfov=0,margin=20/20,guidance_method=cnigfs 默认/launch 调整为 hfov=120,vfov=90,margin=40/30,guidance_method=igfs，更贴近 MATLAB default_params 已对应

未修改

建议项 本次处理
改成“最新帧缓存 + timer 定频 YOLO”的结构 未改。这个会重构 YOLO 节点执行模型，本次按最小改动只放宽同步窗口。
调整 Vc_ref / igfs_vrel_* / terminal_Vc_ref 仍未改。当前只把速度上限和输出映射从明显保守状态调整到 MATLAB 基线附近。
使用 desired_range 做跟踪/避撞安全距离 未改。当前任务是拦截/制导链路稳定性，不改变终端策略。
自动起飞高度建议改小 未改。本项目当前已按用户要求使用 20 m：auto_takeoff_z=-20.0，丢失后保持当前高度。
